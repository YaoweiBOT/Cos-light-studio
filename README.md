# Cos Light Studio · 二次元摄影黑棚练习室

本地运行的摄影布光学习工具。用面积光源和 GPU 路径追踪，观察面光、轮廓光、顶光在真实扫描人脸上的变化。适合先在黑棚条件下练习灯位、光比、光源大小、色温与白平衡。

**这是本地网页应用。** 浏览器负责界面和显卡渲染，本机小服务器负责读取随包文件。无需账号、API Key 或云端渲染服务。发布包包含完整源码、渲染库的构建结果、人脸模型和贴图；正常运行不向 CDN 下载依赖。

## 最快开始：下载发布包后运行

1. **把 ZIP 完整解压到一个文件夹**，不要在压缩包里面直接双击，也不要单独打开 `index.html`。
2. 电脑有 **Python 3.8+ 或 Node.js 22.12+** 其中一个即可。开发和重新构建需要 Node.js；只使用发布包可以仅有 Python。
3. Windows 双击 **`start-windows.cmd`**。浏览器会打开 `http://127.0.0.1:5273/`，保留启动窗口。
4. 使用桌面 Chrome / Edge，开启浏览器硬件加速。首次进入会编译着色器，画面随后逐步收敛。

如果浏览器未自动打开，把上面的本机地址复制进去。按启动窗口中的 Ctrl+C 关闭服务。

macOS 在终端运行 `sh start-macos.command`；Linux 运行 `sh start-linux.sh`。
也可以手动启动：

```sh
python scripts/serve.py
# macOS / Linux 通常用 python3
```

Node.js 启动方式：

```sh
npm start
```

源码和预构建结果匹配时，`npm start` 直接离线启动；源码有变更时，它会准备开发依赖并重建，首次重建需要联网。Python 启动器只运行 `dist/` 中的构建结果。**修改源码后请先重新构建。** 两种启动方式使用相同默认地址，浏览器存档可以共用。

### 离线使用条件

发布 ZIP 已包含 JavaScript、模型、两张贴图和系统字体回退，不必运行 `npm install`。安装好一个启动运行时和浏览器后，可以断网使用。项目不会自动上传方案、渲染图或诊断信息。页面上的署名和帮助外链仅在你主动点击时访问外部网站。

浏览器需支持 **WebGL 2 和浮点颜色缓冲**；渲染速度取决于实际 GPU、驱动、浏览器及画质。这个版本没有 CPU 渲染后备实现，也没有包含 Python / Node.js / 浏览器安装程序。

## 可以练什么

- 三盏独立的矩形或圆形面积灯：位置、距离、高度、瞄准、旋转、宽高、相对功率、色温、绿洋红偏移；可标注每盏对应的灯体（如 AD200Pro II / V860 III）与柔光箱（60/90 八角、深抛等）。
- 灯体面积实际参与光线采样；光源的角尺寸改变阴影柔度。扩大柔光箱时保持总光通量，便于比较近距离照度与柔度的关系。
- 真实扫描人头，可转头、抬低头，支持白模、灰模、皮肤贴图；另有灰、白、金属材质球。
- 黑棚墙面、地面反射、可控环境光，以及白板、黑旗、银板和下方反光板。
- 45° 单灯、伦勃朗、蝴蝶光、分割光、轮廓光等预设，俯视图可拖动灯位。
- 机身与镜头型号：内置索尼 A7C II、佳能 R7 与腾龙 28-75 ƒ/2.8 G2 等，镜头会约束焦距与最大光圈；另有 ISO、快门、曝光补偿、白平衡与可选景深。
- 单灯检查、曝光诊断、A/B 快照、本地方案保存；导出 PNG、JSON 和带灯位图的 HTML 布光卡。

建议先选白模与单灯预设，锁住曝光，再改变一项灯位或尺寸。比起皮肤质感，白模更容易观察鼻影、眼窝和颧骨上的明暗结构。

## 物理边界

采用 Three.js、three-mesh-bvh、three-gpu-pathtracer 的 GPU 路径追踪，计算面积光采样、遮挡、多次反射与 GGX 表面反射。它适合练习布光结构；**还不能作为现实闪灯功率或真人肤质的精确预测器**。

- 功率以一个参考灯的 **1000 lm / 0 EV** 为起点，相对档位每增加 1 EV，总光通量翻倍。同一盏灯内可近似读作闪光功率档（−1 EV ≈ 1/2 输出），但不同灯具之间的绝对输出未标定，不能当作 AD200Pro II 的 Ws 数值；尚无实测灯具配光、柔光箱损耗、格栅或蜂巢模型，深抛罩按同直径均匀圆盘计算。
- 光圈 / ISO / 快门遵循**连续光曝光关系**。快门控制不能直接照搬到同步速度以内的闪光摄影；应固定快门比较布光。
- 人脸为单个扫描头，皮肤使用表面材质与贴图；没有完整皮下散射、独立眼球角膜、细发与真实人体。贴图可能带有扫描采集时残留的明暗。
- 色温、色调、白平衡使用线性 RGB 近似，并非光谱渲染；无法预测 LED 的光谱缺口、CRI / TLCI、化妆品或布料的同色异谱。
- 曝光预览和高光诊断作用于此渲染管线，不是索尼 A7C II、佳能 R7 或其他相机 RAW 的标定结果。屏幕本身也会影响观感。
- 有限采样会产生噪点，多次反射受反弹次数限制。改变灯位后需要等待重新收敛。

## 保存和迁移方案

方案存在浏览器的 `localStorage` 中；不同浏览器、无痕窗口、主机名和端口各自独立。清除浏览数据会删除存档。需要长期保留或分享的方案，请导出 JSON。

从原托管版迁移：在原页面导出方案 JSON，再到本地版导入。两者地址不同，存档不会自动同步。`127.0.0.1` 与 `localhost` 也属于不同地址，建议始终使用启动器给出的地址。

## 如果页面没渲染出来

1. 确认地址是 `http://127.0.0.1:5273/`，启动窗口仍在运行；不要用 `file://` 打开 HTML。
2. 确认完整解压了 `dist/assets/` 与 `dist/models/`。不要混用不同发布版本的文件。
3. 试试桌面 Chrome / Edge，启用“可用时使用图形加速”，重启浏览器。驱动或设备禁用 WebGL 时，本地版仍会受到这个限制。
4. 首次编译着色器可能较慢。遇到错误时，界面会显示原因；点击“复制诊断信息”可以手动复制或下载诊断 JSON，程序不会自动发送。
5. 渲染太慢时调到草稿画质，降低采样数和反弹次数，暂时关闭景深。

端口被其他程序占用时：

```sh
python scripts/serve.py --port=5274
# 或
npm start -- --port=5274
```

不同端口的浏览器存档相互独立。人脸文件损坏时，可以重新解压发布包；开发者可运行 `npm run assets -- --force` 重新获取已注明授权的素材，再运行 `npm run build`。

## 开发

需要 Node.js 22.12+ 和 npm。依赖版本由 `package-lock.json` 锁定。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run build
npm run check
npm start
```

素材已随仓库提供；只有丢失或明确需要重新下载时才运行 `npm run assets`。下载脚本固定到 Three.js r170，并保存来源、许可与 SHA-256。它不会在正常打开页面时运行。

| 路径 | 内容 |
| --- | --- |
| `src/` | 页面、物理计算、状态、场景与渲染代码 |
| `assets/LeePerrySmith/` | 原始扫描、纹理、许可与校验清单 |
| `scripts/` | 本机服务器、构建、校验与 ZIP 打包 |
| `tests/` | 数值关系、导入导出、真实扫描与 BVH、本地 HTTP 测试 |
| `dist/` | 可直接由本机服务器运行的完整构建产物 |

`npm run package` 会重建、运行测试和发布校验，生成 `releases/cos-light-studio-local-v0.3.0.zip`。ZIP 包括源码和构建产物，不包括 `node_modules`、用户浏览器存档或任何托管平台元数据。

## 开源发布

应用原创代码采用 **MIT**。扫描人脸和纹理采用 **CC BY 3.0**，请保留署名和原始许可。依赖保留各自的 MIT 许可；详见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

公开分享包含该扫描人脸的渲染图时，也请在图片说明中保留署名，例如：

> Head scan: Infinite by Lee Perry-Smith / Infinite Realities, based on work at www.triplegangers.com, via Three.js examples, CC BY 3.0 (https://creativecommons.org/licenses/by/3.0/). Scale, materials and lighting modified in Cos Light Studio.

HTML 布光卡已附带署名和许可链接。

本目录可以直接作为 GitHub 仓库根目录。新建一个空的公开仓库后，按 GitHub 给出的命令把本目录提交并推送，再把生成的 ZIP 附加到 Release。保留 `LICENSE`、`THIRD_PARTY_NOTICES.md`、模型许可和 `dist/licenses/`。

`dist/` 有意纳入源码包，便于下载后离线使用；每次修改源码后应重新构建并一起提交。`.gitattributes` 固定换行规则，Windows 启动脚本使用 CRLF。`package.json` 中的 `private: true` 只防止误发到 npm，不影响 GitHub 公开。

## 验证范围

自动检查覆盖光照和曝光的数学关系、方案校验与导出、真实 GLB 的解码与 BVH 构建、本机 HTTP 服务、依赖打包和素材完整性。这些检查不等同于真实 GPU 的画面验收；本发布包尚未在 Windows 桌面显卡上完成浏览器端渲染验证。

若提交渲染问题，请附浏览器版本、系统、GPU（如知道）、界面诊断信息与复现步骤；无需上传个人照片或全部浏览器存档。
